# Platform API Authentication

Platform API requests use a bearer credential in the `Authorization` header. Choose the Platform API first, then choose an access model: OAuth is preferred for per-user integrations, while Glean-issued API tokens remain available for approved admin-managed and global-permission exceptions.

## Request header

```http
Authorization: Bearer <platform_token>
```

## Choose an authentication method

<CardGroup cols={3}>
  <Card title="Glean OAuth Authorization Server" icon="Shield" iconSet="feather">
    Use Glean's OAuth Authorization Server for OAuth access tokens and fine-grained Glean scopes. It must be enabled for your tenant; ask an administrator to verify that it is available. Use a static client for application integrations. DCR is available only when enabled and supported, and has restricted scopes.
  </Card>

  <Card title="External IdP OAuth" icon="Globe" iconSet="feather">
    Use OAuth access tokens issued by a configured identity provider such as Google, Microsoft Entra ID, Okta, or OneLogin.
  </Card>

  <Card title="Glean-issued tokens" icon="Key" iconSet="feather">
    Use user-scoped or global bearer tokens created in the Glean Admin Console. Global tokens also require `X-Glean-ActAs`.
  </Card>
</CardGroup>

## Quick start

1. Confirm that your application has access to the Platform API.
2. For a per-user integration, obtain an OAuth access token from the enabled Glean OAuth Authorization Server or a configured external IdP. For an approved exception, obtain a Glean-issued token.
3. Store the credential securely and provide it in the `Authorization` header.
4. Try the [Platform API Quickstart](/api/platform-api/getting-started).

:::note

Platform API and Client API use the same customer-facing authentication methods. Indexing API operations use Glean-issued tokens and do not accept OAuth. Follow the method-specific setup and scope requirements for the endpoint you are calling.

:::
